# Module 1 — Work Cost Architecture Lock

**Sprint:** M1-WC-0 — Work Cost Architecture Lock
**Module:** Module №1 — Material Data Hub
**Status:** architecture lock

## Core Rule

Стоимость работ в Module №1 не ищется на сайтах, не парсится из прайс-листов, не собирается анализатором и не выводится автоматически из материалов, технологий или смет.

Единственный источник стоимости работ — ручной ввод производителя работ / подрядчика в будущем личном кабинете исполнителя.

## Module Boundary

В Module №1 есть отдельный раздел **“Стоимость работ”**.

Module №1 отвечает только за:

- хранение нормализованного справочника работ;
- хранение стоимости работ, введенной исполнителем;
- валидацию структуры данных;
- статус проверки записи;
- подготовку данных для будущего использования Module №5.

Module №1 не отвечает за:

- расчет сметы;
- расчет технологических объемов;
- поиск стоимости работ на сайтах;
- парсинг прайсов работ;
- создание личного кабинета производителя работ;
- создание пользователей, ролей или компаний Module №3;
- выбор подрядчика для пользователя.

## Normalized Work Dictionary

Справочник работ должен быть нормализованным и заранее заданным.

Исполнитель работ в будущем личном кабинете выбирает работу из справочника, а не вводит произвольное название как новый canonical work item.

Допускается хранить отображаемое пользовательское наименование, но оно не должно заменять нормализованный справочник работ.

## Price Input Model

Исполнитель может указать стоимость двумя способами:

- фиксированная стоимость;
- диапазон стоимости от/до.

Правила:

- фиксированная стоимость хранится в поле **Стоимость**;
- диапазон хранится в полях **Стоимость от** и **Стоимость до**;
- для диапазона значение **Стоимость от** не должно быть больше **Стоимость до**;
- Module №1 не должен автоматически считать среднюю цену диапазона как canonical value;
- цены не должны быть отрицательными;
- единица измерения должна соответствовать выбранному виду работ.

## Work Cost Table Contract

| Поле | Назначение | Правило |
| --- | --- | --- |
| Вид работ | Нормализованная группа / тип работ | Выбирается из справочника |
| Наименование работ | Человеческое название работы | Должно соответствовать выбранному виду работ |
| Стоимость | Фиксированная цена | Используется, если цена не диапазон |
| Стоимость от | Нижняя граница диапазона | Используется только для диапазона |
| Стоимость до | Верхняя граница диапазона | Не меньше значения “Стоимость от” |
| Единица измерения | Единица цены | Выбирается из допустимых единиц для работы |
| Исполнитель | Подрядчик / производитель работ | Ссылка на существующего участника, когда кабинет будет готов |
| Контакты | Контактные данные исполнителя | Не создают пользователя Module №3 |
| Регион | География действия цены | Нужен для регионального применения |
| Статус проверки | Проверено / ожидает проверки / отклонено | Используется для модерации качества данных |
| Дата обновления | Когда цена обновлена исполнителем | Хранится без миллисекунд в пользовательском отображении |

## Explicit Prohibitions

Запрещено:

- искать стоимость работ на сайтах;
- парсить стоимость работ из сайтов, HTML, PDF, XLS, CSV или изображений;
- использовать source adapters для сбора стоимости работ;
- использовать extraction analyzer для определения стоимости работ;
- создавать стоимость работ из scraped/raw/import data;
- смешивать стоимость материалов и стоимость работ;
- считать стоимость работ через Module №2;
- считать сметы в Module №1;
- переносить расчеты Module №5 в Module №1;
- создавать кабинет исполнителя в рамках Module №1;
- создавать пользователей, роли или компании Module №3 из записей стоимости работ.

## Relation To Other Modules

Module №1 хранит и валидирует данные о стоимости работ как справочный слой.

Module №5 позже сможет использовать эти данные для сметы, но расчет сметы остается зоной ответственности Module №5.

Module №2 может использовать справочник работ и технический контекст для технологий, но не должен превращать Module №1 в расчетчик технологических работ.

Module №3 отвечает за пользователей, роли, компании и доступы. Module №1 не создает и не управляет этими сущностями.

## Validation Rules

Минимальная валидация будущего слоя:

- выбранный вид работ существует в нормализованном справочнике;
- наименование работ заполнено;
- указана фиксированная стоимость или корректный диапазон;
- для диапазона заполнены обе границы;
- стоимость и границы диапазона не отрицательные;
- единица измерения допустима для выбранной работы;
- указан исполнитель или совместимая ссылка на будущий профиль исполнителя;
- указан регион или явно разрешено федеральное действие цены;
- статус проверки находится в контролируемом списке;
- дата обновления задана при публикации или изменении стоимости.

## Acceptance Lock

Этот документ фиксирует:

- в Module №1 есть отдельный раздел “Стоимость работ”;
- справочник работ нормализованный и заранее заданный;
- стоимость работ вводится только исполнителем / подрядчиком;
- поддерживаются фиксированная стоимость и диапазон от/до;
- Module №1 только хранит и валидирует эти данные;
- Module №1 не ищет, не парсит и не анализирует стоимость работ с сайтов;
- Module №1 не считает сметы;
- Module №5 позже использует эти данные для сметного расчета.
