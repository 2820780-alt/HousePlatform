# 1. Абсолютные правила

Codex обязан работать по reference image:

```text
docs/references/module3/module3_user_card_reference_v3.png
```

В reference image есть два варианта:

```text
A — Компания / Подрядчик / Поставщик
B — Физ лицо / Инженер
```

## Отклонение от референса

Допускается отклонение размеров и расположения блоков **не более 30%**.

Codex не имеет права:
- менять композицию карточки;
- придумывать собственный layout;
- делать отдельные страницы для сотрудников, модулей или виджетов;
- делать кнопку “Открыть всех”;
- делать кнопку “Открыть все модули”;
- делать кнопку “Открыть все виджеты”;
- делать отдельный mini-editor доступов;
- оставлять горизонтальный скролл;
- оставлять technical/system/debug-информацию в карточке;
- добавлять блок “Техническая информация”.

## Важно

Блок `Техническая информация` больше не нужен.  
Не collapsed, не hidden, не accordion — **вообще не выводить в карточке**.

Raw/debug данные могут оставаться в коде, API, логах или dev tooling, но не должны рендериться в карточке пользователя.

# 2. Композиция карточки

## Верхний header

```text
[breadcrumbs]

[avatar/logo]  [ФИО или название]
               [тип]
               [статусы]
               [контакты / регион / дата / менеджер]
                                                       [Редактировать] [Заблокировать] [Назначить доступ] [...]
```

## Основная сетка

```text
Ряд 1:
[Общая информация]     [Сотрудники и роли / Роли и связи]

Ряд 2:
[Доступ к модулям]     [Доступ к виджетам]
```

Других основных блоков не добавлять.

# 3. Вариант A — Компания / Подрядчик / Поставщик

Использовать для:

```text
Подрядчик
Поставщик
Компания
Строительная компания
```

## Header

Показывать:
- логотип / иконку компании;
- название;
- тип компании;
- статус;
- блокировку;
- email;
- телефон;
- регион;
- дату регистрации;
- назначенного менеджера;
- кнопки действий.

## Ряд 1

### Слева: `Общая информация`

Поля:
- Тип компании;
- ИНН;
- КПП;
- ОГРН;
- Email;
- Телефон;
- Регион;
- Юридический адрес;
- Назначенный менеджер;
- Дата регистрации;
- Последняя активность.

### Справа: `Сотрудники и роли`

Показывать:
- счетчик сотрудников;
- счетчики по ролям;
- список сотрудников;
- ФИО;
- роль в компании;
- статус;
- контакт, если есть.

Если сотрудников много:
- список прокручивается внутри блока;
- vertical hidden scroll;
- отдельной страницы нет;
- кнопки “Открыть всех сотрудников” нет.

## Ряд 2

### Слева: `Доступ к модулям`

Полный список модулей внутри блока.

Формат строки:

```text
Модуль №1: Материалы и база данных    Доступ предоставлен    [toggle]
```

### Справа: `Доступ к виджетам`

Полный список виджетов внутри блока.

Формат строки:

```text
Источники данных                      Доступ предоставлен    [toggle]
```

```text

```

# 5. Модули и виджеты

## Доступ к модулям

Доступы редактируются inline через toggle-переключатели внутри блока.

Запрещено:
- отдельная страница;
- drawer;
- modal с mini-editor;
- кнопка “Открыть все модули”;
- копия вкладки “Доступы” отдельным экраном.

Должно быть:
- список модулей внутри блока;
- toggle справа;
- статус доступа;
- disabled-state;
- короткая человеческая причина недоступности;
- vertical hidden scroll.

## Доступ к виджетам

Аналогично модулям.

Если модуль закрыт:
- виджеты disabled;
- причина: `Недоступно: модуль закрыт`.

```text
workspace
role profile

```

Если эти данные нужны разработчику, они не выводятся в карточку.  
Не создавать блок `Техническая информация`.
